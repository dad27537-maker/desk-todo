# 启动后桌面图标下移一行

修复日期：2026-11-04（Asia/Shanghai）。

## 原因与证据

在双屏、150% DPI 的实际桌面上备份布局后，正常退出并重新启动旧程序。
退出时，格子的逻辑成员重新出现在 Explorer 桌面，占用了一部分普通图标的落点。
旧恢复队列逐个调用 `SelectAndPositionItems(1, ...)`，一个图标的恢复会挤动另一个
图标；先前成功的项目已退出恢复队列，随后采集又会把偏移保存为新布局。

实测退出后 6 个普通图标改变位置；启动并等待恢复后仍有 3 个不在原位，其中
2 个恰好下移 147 像素，与 `IFolderView::GetSpacing()` 返回的一行高度一致。
这是坐标恢复的占位冲突；本次不是通过改变 DPI、网格间距或开机启动路径修复。

## 修复

- 每轮恢复通过同一次 `SelectAndPositionItems` 提交整组未完成目标，包括当前已在
  正确位置的目标，避免把同一布局拆成多个相互影响的单项操作。
- 提交和核验分属不同定时器轮次。COM 返回成功后，仍保留采集保护，直到重新
  读取的位置与目标相符；每次核验的项目数有界，不添加等待循环。
- 保留有限重试、离线屏幕锚点保护，以及原生拖动的新落点优先级。已确认目标和
  被用户拖动替代的目标不参与后续恢复写入。
- 诊断探针增加整组坐标恢复入口，并报告实际坐标、网格间距和 Shell 文件夹标志。

## 验证

146 项原生检查通过，包含整组提交、异步核验前保护锚点和用户落点覆盖检查。
格子恢复测试在正常 Windows 桌面会话通过，覆盖逻辑归组、原位置持久化、
多屏断开重连及显示器标识变化。

真实桌面整组还原 16 个普通图标后，16/16 与备份位置一致；新版正式程序
启动后再次核对，16/16 一致；再次正常退出、启动并等待稳定后，16 个图标的
坐标差全部为 0。核验允许 96-DPI 锚点换算产生最多 1 像素的舍入差。
测试过程保留布局备份并还原了排查前的图标锚点。未实际重启 Windows。
