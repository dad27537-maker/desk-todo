# DeskGo 静态分析与拖拽改进

2026-10-27。二进制分析见 [完整报告](../artifacts/deskgo-rea/REPORT.md)，报告保留载荷哈希、DLL 导入、函数地址、直接调用边和推导边界。没有执行 DeskGo 安装包或载荷，没有把其二进制或反编译代码嵌入本项目。

## 分析所得

外层安装包是 UPX 包装的 x86 PE32，内嵌主载荷含原生 x64 `DesktopMgr64.exe` 和 `Features64.dll`。REA 确认后者有 38 个 DLL、1151 个导入；当前没有配置原生反编译引擎，局部调用图由现有 VS dumpbin、PE `.pdata` 和日志字符串交叉引用补充。

`Features64.dll` 的 `DragBox`（日志推导标签，VA `0x180158A30`）使用光标及缓存屏幕几何；`MovePos`（`0x1800E4E30`）区分所属线程并分派任务；屏幕变化入口（`0x180128000`）统一处理新增屏幕、格子位置和无效边界。借鉴的是拖动几何、落点提交和屏幕恢复分工，不能据此宣称原产品所有下游操作都无阻塞。

## 本项目修改

- **拖动视觉**：按下但未超过起拖阈值时保留源图标；真正起拖后才隐藏源图标并绘制 ghost。渲染前按格子、内容视口及脏区剔除项目，列表文本与图标分别判断可见性。
- **图标提取**：Shell 图标在单独 STA 线程排队提取，首次返回系统占位图；UI 只采纳已完成的 HICON 并创建 D2D bitmap。清缓存用 generation 丢弃过期结果，系统共享图标不再被销毁。
- **真实文件夹移动**：映射目录和旧物理项目的拖出使用拥有生命周期的后台任务。完成时按源路径、格子 ID 和目标目录校验提交，避免旧索引、旧视口或旧屏幕像素影响新布局。普通格子继续逻辑归组，保留真实文件位置。
- **OLE 完成协议**：支持异步的数据源保留数据对象并逐批 `StartOperation` / `EndOperation`；旧数据源在 `Drop` 内用有界消息泵等待后台结果，窗口仍可处理消息。多文件的失败、跳过和销毁均计入整批结果。目标已实际搬动文件时使用优化移动反馈，避免源再次删除原文件。依据 [微软 Shell 数据传输文档](https://learn.microsoft.com/en-us/windows/win32/shell/datascenarios#dragging-and-dropping-shell-objects-asynchronously)。
- **桌面闪烁**：成员巡检只有实际隐藏状态发生变化时才请求 Explorer 异步重绘，移除每轮整桌面同步擦除。
- **热插拔**：枚举失败不再伪造主屏；虚拟边界来自同一次显示器枚举。单一剩余屏幕占据原主屏位置时，未知 ID 不会因几何相同而接管离线锚点。恢复失败路径保持旧锚点，其他路径继续正常采集。
- **跨屏边界**：缓存边界算法先选最大相交面积，全无相交时才按距离选择，避免格子在负坐标、不同屏幕顶部高度的边界被首个枚举屏幕拉回。
- **目录安全**：拒绝目录向自身或后代目录移动；受限环境下安全处理路径规范化失败。完整复制后若原目录递归清理失败，保留目标完整副本及覆盖备份，明确报告状态，不再回滚删除可能唯一剩余的文件。

## 第二屏文件夹、快捷方式弹回修复

旧恢复队列每次拓扑恢复最多遍历所有图标四轮。一个图标即使已经恢复成功，后续轮次仍会再次写入旧位置；用户在恢复间隙把它拖到第二屏，会被下一轮拉回。另一个图标恢复失败时，旧调用方也会暂停所有图标的新位置采集。

恢复成功的目标现在只执行一次；仅失败目标继续有界重试。同时采集已成功目标的新位置，继续保护失败目标，避免自动投射污染旧锚点。

窗口被动接收原始鼠标输入以识别原生 Explorer 桌面拖动，不拦截输入、不模拟鼠标。拖动期间暂停恢复和坐标采集；释放后短暂等待 Explorer 提交位置，再读取选中文件的实际坐标并保存。用户确认的新落点会取消对应旧恢复任务。若释放前后拓扑已变化，丢弃这次采样，防止把断屏投射当成用户落点。接口暂未就绪时最多延迟重试六次。

新增十项回归覆盖：部分恢复成功后再跨屏移动、另一路恢复失败不阻塞采集、普通目录和 `.lnk` 的原生落点优先级、即时保存、负坐标及混合 DPI、关屏后临时主屏投射与再次连接的位置恢复。这些改动已合入正式程序 `DeskTodo.Next/build/Release/DeskTodo.Next.exe`。

## 仍需真实桌面验收的场景

至少验收双屏 100%/150% DPI、左侧负坐标屏幕、主屏切换、拔主屏与副屏、USB-C 扩展坞重连、Explorer 重启，以及这些过程中移动格子和拖放大型目录。核对文件内容、离线锚点、重连后吸附线和完整帧，同时记录拖动帧耗时。

未做物理热插拔回放、全桌面帧耗时测量或所有 Shell 扩展兼容测试，不能承诺所有硬件场景零闪烁、零卡顿。任意第三方 Shell 提取调用永久挂起时，图标线程的退出等待仍可能受影响；单屏设备 ID 改变而缺少足够身份信息时，保守保留旧锚点。
