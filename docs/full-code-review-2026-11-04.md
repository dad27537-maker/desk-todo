# 全项目审核与修复（2026-11-04）

## 审核范围

本轮在此前截图与桌面启动恢复修复的基础上，扩大到当前原生主工程的全部模块、构建与测试入口、早期 Lua 示例。保留工作区中已有的翻译等功能改动。审核采用调用路径检查、MSVC `/analyze`、针对缺陷的回归和实际 Windows 桌面运行验证。

| 范围 | 检查重点 |
| --- | --- |
| App、main、进程间命令 | 启动参数、单实例、消息长度与退出流程 |
| 格子管理、桌面 Shell、多屏布局 | 逻辑归组、映射目录、游戏容器、迁移、持久化、恢复时的坐标冲突 |
| 文件、后台移动、OLE、图标缓存 | 名称冲突、临时文件、失败回滚、资源生命周期、扫描失败 |
| 配置、JSON、布局备份 | 损坏数据、空布局、路径边界、深度限制、原子替换 |
| 截图、贴图、OCR、翻译 | 首次框选、缩放、保存取消、异步结果、剪贴板、识别语言、窗口关闭 |
| 局域网快传与网页 | 上传与下载、文本、鉴权、长度限制、中断、异常清理、目标文件保护 |
| Todo、番茄钟 | 状态文件、编号边界、实际计时、多屏窗口恢复、客户区尺寸 |
| 设置、搜索、D2D 渲染 | 滚动范围、命令转义、注册表字符串、资源初始化失败 |
| 黑洞组件与渲染 | 实际入口、D3D 设备和着色器、透明度、设置校验、进程开关 |
| CMake、PowerShell、Lua 示例 | 构建路径、测试注册、目录含空格、脚本异常输入与异步响应 |

`deps` 中的 OCR SDK/模型和第三方参考仓库不等于自有业务源码；本轮检查其接入和构建行为，没有逐行审计第三方库。早期 Lua 示例未接入当前原生主程序，本机也没有 Lua 宿主，因此仅作静态审核。

## 已修复的主要问题

| 问题 | 原因与修复 |
| --- | --- |
| 桌面普通图标启动后下移 | Explorer 逐项恢复坐标时被旧位置占位挤走。启动恢复改用整组坐标提交；本轮将备份还原路径也统一为批量提交。详见 `startup-layout-recovery.md`。 |
| 截图首次框选、选后缩放、保存位置与取消行为 | 修复鼠标捕获判断，加入八方向缩放和保存选择器；导出前结束活动拖动并提交标注偏移，抬起时采用最终坐标。 |
| 合法空布局重启后出现默认格子、空备份无法还原 | 区分配置缺失和有效空列表，仅缺失时创建默认格子；允许空布局备份还原。 |
| Todo、番茄钟、翻译偏好或备份写入中断后损坏 | 使用独占创建的唯一临时文件、刷新到磁盘后原子替换，失败时保留原文件。 |
| 文件移动临时路径冲突与回滚误删 | 原子创建占位文件；复制使用本次操作独占的临时目录；回滚不删除后来出现的目标文件；占位目录中有其他内容时不清除。 |
| 快传覆盖临时文件或上传期间新出现的目标 | 临时文件以 `CREATE_NEW` 创建；最终提交不覆盖既有目标；异常和中断只清理本次临时数据。 |
| 快传目录错误、线程异常、超长请求头 | 回收初始化资源并捕获工作线程异常；完整请求头再次校验 64 KiB 限额。 |
| 深层 JSON 或无效格子标识 | 未知字段跳过限制嵌套深度；限制配置大小；拒绝目录穿越字符、重复标识和路径内嵌 NUL。 |
| 目录扫描部分失败被当作成功 | 检查枚举结束错误，失败返回空结果和失败状态，避免把残缺列表当作完整目录。 |
| 番茄钟随界面卡顿变慢 | 用单调时钟累计真实经过时间，保留暂停前小数秒，批量跨越完整周期并防止计数溢出。 |
| 组件移到剩余屏幕后尺寸异常、拉伸客户区错误 | 先计算原宽高，再限制到工作区；处理极端坐标和小屏幕；保留系统提出的新客户区。 |
| Todo 编号溢出后与既有项目重复 | 遇到最大编号时查找第一个未占用编号。 |
| 黑洞按钮启动后没有效果 | 旧入口调用参考目录中的空实现。启用项目内 D3D11 后端，增加独立分层渲染窗口和桌面透镜合成，保留空闲模式与设置加载；移除构建对占位参考代码的依赖。 |
| 黑洞异常参数与子进程句柄泄漏 | 归一化 NaN/无穷值，校验注册表类型和大小；重新启动前关闭已退出进程句柄。 |
| 渲染资源创建失败后状态不一致 | 工厂初始化失败回滚引用与对象；检查绘制所需画刷和渲染目标。 |
| 路径含渲染参数文字时误入黑洞模式 | 解析真实 argv 并匹配独立参数，不在整个命令行上搜索子串。 |
| 进程间命令越界读取 | 校验长度、对齐和结尾 NUL，拒绝内嵌 NUL；发送端检查接收结果。 |
| 窗口嵌套消息循环退出后引用失效 | 退出前销毁仍存在的窗口，保留并重新投递退出消息；全局消息循环不再处理 `GetMessage` 的错误返回。 |
| 搜索包含引号或特殊字符时参数错误 | Windows 参数转义和 UTF-8 URI 编码；背景搜索不保存过期窗口句柄；搜索路径长度和注册表字符串终止校验。 |
| 设置页底部内容无法通过滚动条访问 | 修正滚动范围与可见页高度的关系。 |
| OCR 转 LaTeX 的 CRLF 多出换行、复制失败路径 | 先统一换行，再转换；检查剪贴板内存锁定结果。 |
| 根目录构建和测试脚本指向旧工程 | 统一到 `DeskTodo.Next`，自动发现 CMake，注册 CTest，隔离每组测试工作目录；修复 OCR 安装目录含空格时的解压参数。 |
| Lua 示例中的异常设置、主题缺失、过期网络响应 | 番茄钟间隔至少为 1；主题有默认值；禁用媒体按钮不触发控制；RSS 按请求和 URL 匹配响应。 |

## 验证记录

最终完整回归 **16/16 通过，0 失败**（30.34 秒）；正式 Release 主程序构建成功，正常退出旧版后已启动修复版，进程响应正常。`git diff --check` 通过。

实际联网验证通过：人工生成的英文截图经本地 OCR 后翻译为中文，另验证 Google 日文翻译及 MyMemory 中文翻译。没有发送用户截图或个人内容。

最终回归还修复了测试自身的时间竞争：翻译窗口的取消/关闭检查由固定等待 250 毫秒改成显式控制模拟请求完成，避免机器繁忙时误报。空布局检查同时确认“没有格子”是成功初始化，应用仍可继续使用。

自动回归包含 15 个原生测试程序及 1 个 Node 网页测试。新增覆盖空布局、原子保存失败保护、文件占位保护、畸形命令、深层 JSON、计时补偿、编号溢出、组件窗口缩放和实际 D3D 帧输出。窗口/网络测试在真实 Windows 宿主环境运行，受限沙箱的连接及 Shell 限制不当作产品缺陷。

黑洞还单独通过了实际子进程窗口创建和正常关闭检查；首次初始化包含着色器编译，不能把固定 6 秒内未找到窗口直接判为启动失败。

## 验证边界

- 本轮没有重启 Windows，没有进行物理显示器或扩展坞断电测试。此前对 16 个真实桌面图标做过两次应用重启位置对比，不能代替系统冷启动。
- 多屏坐标、移除显示器和重连逻辑有自动回归，仍不代表所有显卡驱动和 DPI 组合已验证。
- Lua 示例只有静态检查；第三方 OCR SDK 的静态分析告警不等于已证实的运行缺陷。自有代码仍有大栈缓冲区提示，未把这些提示直接计为已修复缺陷。
- 在线服务的实际可用性随网络和服务变化。离线模拟测试与真实联网测试分别记录。
- 审核覆盖和回归通过不表示不存在尚未触发的缺陷；本文列明已确认问题、处理方式和实际验证范围。
